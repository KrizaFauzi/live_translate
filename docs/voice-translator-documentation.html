Ringkasan Proyek

Visi, masalah yang diselesaikan, dan tolok ukur keberhasilan

Visi

Voice Translator adalah aplikasi web berbasis AI untuk terjemahan audio dua arah antara Bahasa Indonesia (ID) dan Bahasa Inggris (EN). Seluruh pemrosesan berjalan lokal melalui Docker dengan model open-source — tidak ada data yang meninggalkan mesin pengguna.

Latar Belakang Masalah

Pengguna membutuhkan cara yang sederhana dan privat untuk menerjemahkan percakapan lisan. Solusi yang ada saat ini memiliki dua kelemahan besar: layanan cloud mengirim rekaman suara ke server pihak ketiga (masalah privasi), sementara solusi self-hosted umumnya menuntut keahlian teknis yang tinggi untuk dipasang.

🔒 Privasi sebagai fondasi. Tidak ada panggilan API eksternal selama penggunaan normal — satu-satunya koneksi internet adalah unduhan model AI saat pertama kali dijalankan.

Metrik Keberhasilan (Target MVP)

Pengalaman Pengguna Inti

  • Tahan tombol untuk bicara — rekam suara dengan interaksi hold-to-talk (tekan = merekam, lepas = proses).
  • Transkripsi instan — teks asli muncul segera setelah rekaman diproses.
  • Terjemahan dua arah — sakelar mode ID → EN / EN → ID menentukan arah terjemahan.
  • Tampilan berdampingan — teks asli dan hasil terjemahan ditampilkan dalam panel ganda yang jelas.

02

Fitur Utama

Kemampuan aplikasi pada rilis MVP

🎙️

Perekaman Suara Hold-to-Talk

Merekam audio langsung dari mikrofon browser melalui API MediaRecorder. Cukup tahan tombol besar untuk merekam, lepaskan untuk memproses. Audio tersimpan sebagai blob webm/mp3.

📝

Speech-to-Text Akurat

Model faster-whisper versi tiny (int8, CPU) mengubah suara menjadi teks sekaligus mendeteksi bahasa yang digunakan — dioptimalkan untuk kecepatan tanpa mengorbankan akurasi.

🔄

Terjemahan Dua Arah ID ⇄ EN

Dua model MarianMT spesialis — opus-mt-id-en dan opus-mt-en-id — menerjemahkan teks sesuai mode aktif, dengan indikator visual arah terjemahan.

🖥️

Antarmuka Panel Ganda

Hasil transkrip asli dan terjemahan tampil bersebelahan dalam layout dua panel yang bersih, dibangun dengan React + TailwindCSS yang responsif.

🐳

Deployment Satu Perintah

Seluruh sistem berjalan sebagai dua kontainer Docker (frontend + backend) yang diluncurkan dengan satu perintah docker-compose up — termasuk ffmpeg untuk pra-pemrosesan audio.

🛡️

Penanganan Error yang Ramah

Izin mikrofon yang ditolak, kegagalan transkripsi, atau error terjemahan ditangani dengan pesan yang jelas; file audio sementara otomatis dibersihkan setelah diproses.

Alur Kerja End-to-End

Dari suara ke terjemahan dalam 6 langkah

1

Pengguna merekam suara

Tombol mikrofon ditekan-ditahan — MediaRecorder di browser menangkap potongan audio secara langsung.

2

Audio dikirim ke backend

Rekaman dirakit menjadi blob webm/mp3 lalu dikirim via POST /api/transcribe sebagai multipart/form-data.

3

Whisper mentranskripsi

ffmpeg menyiapkan audio, faster-whisper menghasilkan teks beserta bahasa yang terdeteksi (original_text, detected_language).

4

Transkrip tampil & diteruskan otomatis

Teks asli langsung muncul di panel kiri; frontend otomatis meneruskannya ke POST /api/translate sesuai mode aktif.

5

MarianMT menerjemahkan

Model opus-mt-id-en atau opus-mt-en-id menerjemahkan teks dan mengembalikan translated_text.

6

Hasil tampil & bersih-bersih

Terjemahan muncul di panel kanan; file audio sementara di backend dihapus otomatis setelah selesai diproses.

Target performa: total waktu end-to-end < 15 detik untuk klip audio 5–10 detik — transkripsi beam_size=5, terjemahan direct pipeline tanpa beam search.

Referensi API

Tiga endpoint REST pada backend FastAPI

POST/api/transcribe

Mentranskripsi file audio menjadi teks menggunakan faster-whisper.

Request: multipart/form-data — field audio (audio/webm atau audio/wav)
Response 200: { "original_text": "...", "detected_language": "id" | "en" }
Error 500: { "detail": "pesan kesalahan" }
POST/api/translate

Menerjemahkan teks antara Bahasa Indonesia dan Bahasa Inggris menggunakan MarianMT.

Request: application/json — { "text", "source_lang", "target_lang" }
Response 200: { "translated_text": "..." }
Error 500: { "detail": "pesan kesalahan" }
GET/health

Health check untuk memantau kesiapan layanan — dipakai juga oleh Docker healthcheck pada mode produksi.

Response 200: { "status": "ok" }
Catatan: pada lingkungan development backend di-expose di port 8008 (internal kontainer 8000); frontend produksi mengakses API melalui path relatif via reverse proxy nginx.

Cara Menjalankan

Persyaratan: Docker & Docker Compose terpasang

1 · Siapkan konfigurasi (opsional)

Salin variabel lingkungan ke file .env di root proyek — misalnya HF_TOKEN jika mengunduh model dari HuggingFace yang memerlukan autentikasi.

2 · Mode Development

# Bangun & jalankan kedua kontainer
docker-compose up --build

# Frontend  → http://localhost:3005
# Backend   → http://localhost:8008/health

3 · Mode Produksi

# Image produksi: frontend dibangun (nginx),
# backend dengan healthcheck & restart policy
docker-compose -f docker-compose.prod.yml up --build -d

Yang Terjadi Saat Pertama Kali Dijalankan

  • Kontainer backend mengunduh model Whisper tiny dan kedua model MarianMT dari HuggingFace (butuh koneksi internet sekali ini saja).
  • Model disimpan di Docker volume model_cache — jalankan ulang berikutnya sepenuhnya offline dan lebih cepat.

Batasan & Rencana Pengembangan

Ruang lingkup MVP dan arah pengembangan berikutnya

Di Luar Lingkup MVP
  • Autentikasi & akun pengguna
  • Penyimpanan riwayat percakapan
  • WebSocket (memakai REST API saja)
  • Pemilihan model via UI (tiny & MarianMT fixed)
  • Packing model offline (unduh saat run pertama)
  • Deteksi bahasa di luar output Whisper
Rencana Pasca-MVP
  • Medium: Web Worker agar pemrosesan AI tidak membekukan UI
  • Medium: Strategi caching model untuk restart lebih cepat
  • Low: Pasangan bahasa tambahan (Jawa, Korea, dll.)
  • Low: Pemrosesan batch untuk file audio panjang
  • Low: Putar ulang audio asli & hasil terjemahan
  • Low: Pilihan ukuran model (tiny / base / small)

Kriteria Selesai MVP

  • Kontainer Docker terbangun dan berjalan dengan docker-compose up --build tanpa error.
  • Frontend dapat diakses, backend merespons {"status": "ok"} pada endpoint health.
  • Pengguna dapat merekam, melihat transkrip, dan menerima terjemahan dua arah ID ⇄ EN dengan benar.
  • File audio sementara dibersihkan otomatis; konsol browser bebas error pada pemakaian normal.
Dibangun dengan prinsip: privat secara default. Voice Translator membuktikan bahwa AI speech-to-text dan machine translation kelas produksi bisa berjalan sepenuhnya di mesin sendiri — tanpa biaya API, tanpa langganan, tanpa data yang bocor keluar.
