Ringkasan Proyek

Visi, masalah yang diselesaikan, dan tolok ukur keberhasilan

Visi

Voice Translator adalah aplikasi web berbasis AI untuk terjemahan audio dua arah antara Bahasa Indonesia (ID) dan Bahasa Inggris (EN). Seluruh pemrosesan berjalan lokal melalui Docker dengan model open-source — tidak ada data yang meninggalkan mesin pengguna.

Latar Belakang Masalah

Pengguna membutuhkan cara yang sederhana dan privat untuk menerjemahkan percakapan lisan. Solusi yang ada saat ini memiliki dua kelemahan besar: layanan cloud mengirim rekaman suara ke server pihak ketiga (masalah privasi), sementara solusi self-hosted umumnya menuntut keahlian teknis yang tinggi untuk dipasang.

🔒 Privasi sebagai fondasi. Tidak ada panggilan API eksternal selama penggunaan normal — satu-satunya koneksi internet adalah unduhan model AI saat pertama kali dijalankan.

Metrik Keberhasilan (Target MVP)

< 10 dtkLatensi transkripsi audio 10 detik
< 5 dtkLatensi terjemahan teks
> 85%Akurasi pengenalan suara (audio jernih)
0Transmisi data ke layanan eksternal

Pengalaman Pengguna Inti

  • Tahan tombol untuk bicara — rekam suara dengan interaksi hold-to-talk (tekan = merekam, lepas = proses).
  • Transkripsi instan — teks asli muncul segera setelah rekaman diproses.
  • Terjemahan dua arah — sakelar mode ID → EN / EN → ID menentukan arah terjemahan.
  • Tampilan berdampingan — teks asli dan hasil terjemahan ditampilkan dalam panel ganda yang jelas.

Perekaman Suara Hold-to-Talk

Merekam audio langsung dari mikrofon browser melalui API MediaRecorder. Cukup tahan tombol besar untuk merekam, lepaskan untuk memproses. Audio tersimpan sebagai blob webm/mp3.

Speech-to-Text Akurat

Model faster-whisper versi tiny (int8, CPU) mengubah suara menjadi teks sekaligus mendeteksi bahasa yang digunakan — dioptimalkan untuk kecepatan tanpa mengorbankan akurasi.

Terjemahan Dua Arah ID ⇄ EN

Dua model MarianMT spesialis — opus-mt-id-en dan opus-mt-en-id — menerjemahkan teks sesuai mode aktif, dengan indikator visual arah terjemahan.

Antarmuka Panel Ganda

Hasil transkrip asli dan terjemahan tampil bersebelahan dalam layout dua panel yang bersih, dibangun dengan React + TailwindCSS yang responsif.

Deployment Satu Perintah

Seluruh sistem berjalan sebagai dua kontainer Docker (frontend + backend) yang diluncurkan dengan satu perintah docker-compose up — termasuk ffmpeg untuk pra-pemrosesan audio.

Penanganan Error yang Ramah

Izin mikrofon yang ditolak, kegagalan transkripsi, atau error terjemahan ditangani dengan pesan yang jelas; file audio sementara otomatis dibersihkan setelah diproses.

Referensi API

Tiga endpoint REST pada backend FastAPI

POST /api/transcribe

Mentranskripsi file audio menjadi teks menggunakan faster-whisper. Menerima file audio via multipart/form-data.

Request: multipart/form-data — field audio (audio/webm, audio/wav, audio/mp3, audio/ogg)
Response 200: { "original_text": "string", "detected_language": "id" | "en" }
Error 400: { "detail": "File audio tidak valid atau kosong" }
Error 500: { "detail": "Kesalahan internal server" }

Contoh curl

# Transkripsi file audio (webm/mp3/wav)
curl -X POST http://localhost:8008/api/transcribe \
  -F "audio=@recording.webm" \
  -H "Accept: application/json"

# Contoh response sukses
{
  "original_text": "Halo, apa kabar?",
  "detected_language": "id"
}
POST /api/translate

Menerjemahkan teks antara Bahasa Indonesia dan Bahasa Inggris menggunakan MarianMT.

Request: application/json — { "text": "string", "source_lang": "id"|"en", "target_lang": "id"|"en" }
Response 200: { "translated_text": "string" }
Error 400: { "detail": "Pasangan bahasa tidak didukung" }
Error 500: { "detail": "Kesalahan internal server" }

Contoh curl

# Terjemahkan Indonesia → Inggris
curl -X POST http://localhost:8008/api/translate \
  -H "Content-Type: application/json" \
  -d '{"text": "Halo dunia", "source_lang": "id", "target_lang": "en"}'

# Terjemahkan Inggris → Indonesia
curl -X POST http://localhost:8008/api/translate \
  -H "Content-Type: application/json" \
  -d '{"text": "Hello world", "source_lang": "en", "target_lang": "id"}'

# Contoh response sukses
{
  "translated_text": "Hello world"
}
GET /health

Health check untuk memantau kesiapan layanan — dipakai juga oleh Docker healthcheck pada mode produksi.

Response 200: { "status": "ok" }

Contoh curl

curl http://localhost:8008/health
# {"status": "ok"}
Catatan port: pada lingkungan development backend di-expose di port 8008 (internal kontainer 8000); frontend produksi mengakses API melalui path relatif via reverse proxy nginx.

Pemecahan Masalah Umum

Diagnosis cepat dan solusi untuk kendala yang sering ditemui

GejalaPenyebab KemungkinanSolusi
Mikrofon tidak terdeteksi / izin ditolak Browser memblokir akses mikrofon; bukan konteks aman (bukan localhost/https) Berikan izin mikrofon pada browser; pastikan mengakses via localhost (konteks aman). Di Chrome: 🔒 → Site settings → Microphone → Allow.
Health check gagal / stuck saat startup Model belum selesai diunduh; koneksi internet lambat; kekurangan memori Tunggu unduhan model pertama selesai; cek log docker-compose logs -f backend; pastikan RAM >= 4 GB.
Port bentrok (3005 / 8008 sudah dipakai) Proses lain menggunakan port yang sama Ubah mapping port di docker-compose.yml (mis. 3006:3005, 8009:8000) atau hentikan proses yang bentrok.
Transkripsi kosong / "No speech detected" Audio terlalu pendek (<0.5s), terlalu bising, atau format tidak didukung Bicara lebih jelas & minimal 1-2 detik; periksa level mikrofon; coba format WAV.
Terjemahan salah arah / bahasa tidak sesuai Mode toggle tidak sinkron dengan bahasa terdeteksi Whisper Pastikan sakelar mode (ID→EN / EN→ID) sesuai bahasa yang Anda bicarakan; Whisper mendeteksi otomatis tapi terjemahan mengikuti mode UI.
Latensi tinggi (>30 detik) CPU terbatas, tidak ada GPU, model besar, atau thermal throttling Gunakan GPU jika tersedia (CUDA + float16); tutup aplikasi berat lain; pertimbangkan model tiny (default).
Frontend tidak bisa konek ke backend (CORS / network error) Vite proxy tidak aktif; backend belum siap; akses via IP bukan localhost Pastikan vite.config.js proxy /api → http://backend:8000; akses frontend via localhost:3005 bukan IP LAN.
Error "CUDA out of memory" VRAM GPU tidak cukup untuk model Set device=cpu atau compute_type=int8 di utils/device.py; atau gunakan model tiny.
Model MarianMT tidak ditemukan / download gagal Koneksi ke HuggingFace terblokir; HF_TOKEN diperlukan Set HF_TOKEN di .env; cek firewall/proxy; model di-cache setelah berhasil sekali.

Model Keamanan & Privasi

Desain privat secara default, tanpa kompromi

🔒 Prinsip: Data Anda tidak pernah meninggalkan mesin Anda. Voice Translator dirancang dari awal untuk berjalan 100% offline setelah setup awal. Tidak ada telemetri, tidak ada analytics, tidak ada panggilan ke API eksternal saat runtime.

Aliran Data

  • Audio input → tertangkap browser → dikirim ke backend lokal via HTTP pada localhost → diproses → dihapus.
  • Teks transkrip & terjemahan → hanya ada di memori browser & backend sementara → ditampilkan ke UI → tidak disimpan ke disk/database.
  • Model AI → diunduh sekali dari HuggingFace saat pertama run → disimpan di volume Docker lokal → digunakan offline selamanya.

Surface Area Keamanan

KomponenRisikoMitigasi
Microphone APIAkses audio perangkatHanya aktif saat tombol ditekan; indikator visual browser; konteks aman (localhost) wajib.
Network (localhost)Traffic HTTP lokalHanya bind ke 127.0.0.1; tidak expose ke LAN kecuali dikonfigurasi manual.
Docker VolumePenyimpanan modelHanya berisi file model read-only; tidak ada data user.
File temporer audioSisa file di diskDihapus otomatis di block finally setelah transkripsi selesai.
DependenciesSupply chain attackPin versi di requirements.txt & package-lock.json; audit berkala.

Checklist Hardening (Produksi)

  • Gunakan docker-compose.prod.yml (nginx + healthcheck + restart policy).
  • Batasi akses jaringan: jangan publish port 8008 ke interface publik; gunakan reverse proxy dengan TLS.
  • Set HF_TOKEN hanya jika diperlukan; jangan commit ke repo.
  • Jalankan kontainer sebagai non-root (sudah default di python:3.10-slim).
  • Audit dependensi: pip-audit / npm audit berkala.

Lisensi

Voice Translator dirilis di bawah lisensi MIT License — bebas digunakan, dimodifikasi, dan didistribusikan untuk tujuan komersial maupun non-komersial, dengan mempertahankan hak cipta dan notifikasi lisensi.

Model AI yang digunakan:

  • faster-whisper (tiny) — berbasis Whisper OpenAI, lisensi MIT; model weights CC-BY-NC 4.0 (non-komersial) — gunakan model tiny yang dikonversi CTranslate2.
  • Helsinki-NLP/opus-mt-id-en & opus-mt-en-id — lisensi Apache-2.0 (model & kode).
⚠️ Perhatian: Weight model Whisper asli (OpenAI) memiliki klausul non-komersial. Variasi faster-whisper menggunakan model yang dikonversi CTranslate2; untuk penggunaan komersial, pertimbangkan model alternatif seperti distil-whisper atau model ASR sepenuhnya open-source (mis. whisper.cpp dengan model public domain).

  1. Fork repositori & buat branch fitur: git checkout -b feat/nama-fitur

  4. Jalankan linter: ruff check backend / npm run lint (frontend).
  5. Commit dengan pesan konvensional: feat: tambah dukungan bahasa XX
  6. Buat Pull Request ke main dengan deskripsi jelas & screenshot jika UI berubah.

Area kontribusi yang dibutuhkan: model bahasa baru, optimasi latency, aksesibilitas (WCAG 2.1 AA), dokumentasi bahasa lain, packaging (Homebrew, Scoop, AUR).

Glosarium

STT (Speech-to-Text)
Teknologi mengubah sinyal audio suara menjadi teks tertulis. Di proyek ini: faster-whisper.
MT (Machine Translation)
Terjemahan otomatis teks dari bahasa sumber ke target. Di proyek ini: MarianMT (Helsinki-NLP).
faster-whisper
Implementasi CTranslate2 dari Whisper OpenAI — 4-5x lebih cepat, memori lebih rendah, kompatibel CPU/GPU.
MarianMT
Framework Neural Machine Translation efisien dari Helsingin yliopisto; model Opus-MT terlatih pada data OPUS.
CTranslate2
Engine inferensi Transformer cepat (INT8, FP16) untuk CPU/GPU; digunakan faster-whisper & MarianMT.
Beam Search
Algoritma decoding yang menjelajahi multiple hipotesis; beam_size=5 berarti 5 jalur paralel.
INT8 Quantization
Kompresi bobot model dari FP32 ke INT8 (8-bit) — ukuran 4x lebih kecil, inferensi 2-4x lebih cepat di CPU.
Docker Volume
Mekanisme penyimpanan persisten terkelola Docker; data bertahan setelah kontainer dihapus.
Hold-to-Talk
Pola UX: tekan tahan untuk merekam, lepaskan untuk memproses — mencegah rekaman tidak sengaja.
VAD (Voice Activity Detection)
Deteksi keberadaan suara dalam audio; digunakan untuk chunking/segmentasi otomatis.
TTS (Text-to-Speech)
Sintesis suara dari teks; rencana masa depan untuk output audio terjemahan.
